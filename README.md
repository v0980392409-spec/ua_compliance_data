# ua_compliance_data

Канал роздачі пакетів законодавчих даних для застосунку
[ua_compliance](https://github.com/v0980392409-spec/ua_compliance): параметри (МЗП, прожитковий
мінімум, ставки), класифікатори (КАТОТТГ, КВЕД).

**Кожен пакет — це реліз цього репозиторію з одним zip-вкладенням.** Екземпляри раз на добу
забирають нові релізи, перевіряють підписи й показують передпоказ змін; застосовує пакет людина
з роллю «Відповідальний за законодавство». Автоматичного застосування немає свідомо.

## Чому сюди можна не довіряти

Сервер роздачі вважається недовіреним. Довіра виникає лише на екземплярі:

- маніфест пакета підписано **двома з трьох** ключів Ed25519 (формат minisign); відкриті ключі
  закріплені в коді застосунку й змінюються тільки його релізом;
- версія в межах каналу лише зростає — старий пакет не підсунути;
- у маніфесті строк придатності й хеш кожного файла;
- у пакеті тільки CSV: код, формули й друковані форми їдуть релізом застосунку.

Тому підмінений реліз або чужий пакет у цьому репозиторії екземпляр просто відкине.

## Як випустити пакет

Потрібні: `minisign` (`brew install minisign`), копія `ua_compliance` поруч із цим
репозиторієм, Python 3 з пакетом `cryptography`.

1. Підготувати маніфест (CSV перевіряється кодом застосунку одразу):

   ```bash
   python3 publish.py prepare parameters 20261101 --expires 2027-03-31 \
       --min-app 0.1.0 --notes "Закон про Державний бюджет на 2027 рік: МЗП" parameters.csv
   ```

2. Підписати `build/parameters-20261101/manifest.json` двома ключами — команди друкує `prepare`.
3. Зібрати й перевірити (підписи й поріг — кодом застосунку):

   ```bash
   python3 publish.py pack build/parameters-20261101
   ```

4. Опублікувати реліз командою, яку друкує `pack`. Тег — `<канал>-<версія>`.

Версія — ціле число, що росте в межах каналу (зручно `РРРРММДД`). Виправлення помилки — новий
пакет з більшою версією: застосований пакет не скасовується.

Схеми CSV — у контракті пакета (`specs/023-legal-parameters-updates/contracts/package-manifest.md`
репозиторію вимог).
